Wiki · proposal

A page is data, not markdown

The page is a list of typed blocks. Text is stored as claims — one statement each — and every claim points at the exact words in a source it rests on.

Why not markdown

  • Citations need to point at a span, not a URL: “these words in Maja’s email”. Markdown has nowhere to keep that, so it would end up in a side file that drifts.
  • Claims need identities. When a source changes or is removed, the agent can find every statement that rested on it and re-check, rewrite or flag it.
  • Embeds stay live. A timeline, task list or place is a query into Calendar, Tasks or Places — the page shows today’s truth instead of a pasted copy.
  • Questions are tracked: open until answered; the answer is saved as a new source and the page cites it.

What you still get

  • Export to markdown at any time — claims become sentences, citations become footnotes, embeds become a snapshot.
  • Only the agent writes. You steer it in chat (“add the flight times”, “Maja is vegetarian now”); every statement it writes must cite a stored source, including what it looks up itself.
  • Every source is a stored copy — a conversation, a transcribed voice note, a document, an image or a fetched web page — saved as it was when captured, with an origin URI back to where it came from. The original can change or vanish; the citation can't.
